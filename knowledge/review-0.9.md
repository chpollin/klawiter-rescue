# Review 0.9

Findings of the external review of the 0.9 release candidate (2026-08-27, four parallel review agents over pipeline, frontend, data model and tests/CI, plus a CSS deep audit; load-bearing findings verified directly against source, raw bytes and generated artifacts). This document preserves the findings before implementation. Use the current status and remediation links to determine which findings remain open; do not remove historical evidence.

## Overall verdict

The substance holds. The atomic I/O layer, the byte-identity CI check, the contested-claim model, the gate validation and the vocabulary publication are sound; the test suite tests real behaviour (the category oracle against MediaWiki's own `zweig_categorylinks` table is the strongest test in the repository); routing, error states, escaping and the mobile drawer in the frontend are carried through completely. The findings concentrate on four spots: one real data defect in redirect handling, two functional defects in the curation surface, contradictory publication metadata, and a provenance chain open at both ends.

## Before acceptance (0.9 → 1.0)

### Real defects in data and interface

1. **Redirect decoration contaminates published data.** `pipeline/04_classify.py:148` writes a display form (`Title (→ id)`) into a data field. Verified consequences: all 1,546 redirect entries in `klawiter.jsonld` carry the literal as `klawiter:redirectTarget`; 655 keys of the frontend redirect map are garbage keys; the resolution branch `05_to_jsonld.py:102-111` is dead code (`direct.get(target)` never matches the decorated string); 109 of the 120 "unresolved" seeAlso references are redirect page titles this branch should resolve. The claim in `data.md` and `testing.md` that the remaining broken references are genuine red links is therefore false. Fix: drop the decoration, put the resolved page id in its own field. Small, but changes reproduction-checked artifacts and the baseline; `test_census.py` only asserts a lower bound on the map size, so add a regression test.
2. **Keyboard listeners on the candidate queue accumulate.** `docs/js/curate.js:314` adds a keydown listener on `#agent-queue` on every render; the element is created once in `_build` and only its innerHTML is replaced, and `Edit.decideAgentSubject` re-renders after every decision. After n decisions one keypress fires n times, so `y` decides several subjects at once. Move the registration to `_build` or guard with a flag. Small.
3. **Explore filter hand-over yields an empty result list.** `docs/js/explore.js:746` writes `params.language = f.languages[0]` raw into the hash; the placeholder `Not recorded` never matches (`app.js` compares raw against `e.language`, absent means undefined), so "View all N entries" shows 0 results, and with multi-select every language but the first is silently dropped so list and visualization disagree. Route the placeholder and the multi-select case through `App.showCustomResults`, as the country case at `explore.js:761` already does. Small.
4. **The correction overlay cannot fail.** `pipeline/apply_patches.py` reads the authoritative corrections store with soft defaults (`doc.get("patches", [])`, `data.get("entries", [])`), treats `not_found` and `invalid` as warnings and always exits 0, which the runner reads as success. Additionally `validate_patch` checks neither the type of `pageId` (a string never finds its integer-keyed target) nor the form of `edited_at` (raw string sort scrambles last-wins order under mixed offsets). Read both keys strictly, exit non-zero on `not_found`/`invalid`, validate both fields; this also hardens `validate-patch.yml`, which imports the same function. Small.
5. **Small pipeline hardenings** (each small to trivial):
   - Refreezing tools write gate-2 evidence before checking batch failures (`reconcile_locations.py:322` vs `:325-332`, `reconcile_agents.py:172` vs `:177-183`); abort before writing.
   - A swallowed SPARQL error does not increment `batch_failures` (`reconcile_locations.py:294-295`), and `list(set(...))` at `:286` makes batch boundaries hash-random; use the counter and `sorted(set(...))`.
   - `MAX_VALID_YEAR = now().year + 5` in `lib/config.py:113` flows into byte-checked artifacts via `lib/patterns.py`; currently latent (no year token above 2031 in the source), but it makes byte identity calendar-year-bound. Freeze to a corpus-justified constant.
   - `segment_editions.py:89` prioritizes on the flag `page-count-notation-review`, which nothing emits; `lib/editions.py` sets `normalized-page-count-notation`. Entries with normalized page-count notation fall through to P2. The existing test checks the real name and misses the mismatch.
   - Two replacement pairs in `lib/encoding.py:188-189` and `:196-197` carry bare `Ä`/`â` instead of the full mojibake sequence, corrupting legitimate German Ä and French â before `verify.py` compares; the second entries of both pairs are unreachable.
   - Minor: `inject_provenance.py:94` repeats `TRACKED_FIELDS` as a literal; `reconcile_locations.py:40` / `reconcile_agents.py:37` call `sys.stdout.reconfigure` without the `hasattr` guard `lib/config.py` already has; `validate_reconciliation.py:92` reports an agent QID error as a location; `:122-124`/`:152-154` accept an occurrence without a hash; `lib/reconciliation.py:456`/`:869` turn a structurally deviant agent file into a silent empty set that the validator confirms because it rebuilds with the same defaults.

### Publication metadata (decisive for the DOI release)

6. **`CITATION.cff` says `license: MIT`** while README, site footer and both graphs declare CC BY 4.0 for the data; Zenodo reads exactly this file. Also: `orcid: ""` violates the CFF 1.2.0 pattern (remove the field), `version` and `identifiers` are missing, `date-released` is stale; for a tag-driven release, version and date must match the tag, and the concept DOI belongs in `identifiers` after the first release.
7. **The repository already claims acceptance.** `pyproject.toml` says `1.0.0` and `.github/baseline-metrics.json` says `2026-08-27-v1.0-freeze` while the declared state is 0.9. Pull both to 0.9.
8. **`LICENSE` contains only MIT text** although the README points there for the dual licensing. Recommendation: `LICENSES/MIT.txt` plus `LICENSES/CC-BY-4.0.txt`, `LICENSE` as a scope statement. Missing for a clean release: `.zenodo.json`, `CHANGELOG.md` (the journal records sessions, not release deltas), a tag, and one consistent publisher statement (site names the Stefan Zweig Zentrum Salzburg, `about.md` names Stefan Zweig Digital, `CITATION.cff` names nobody; operator decision pending).
9. **Audit artifacts undermine trust.** `data/output/audits/final-independent-verification.json` leaks the absolute local path of the working machine and still points a JSON pointer at the pre-rename `klawiter:reviewAction`; `production-readiness-final.json` carries eleven artifact hashes that all diverge from the current files (audit of 08-21 against artifacts of 08-27). Relativize the path, mark both as dated snapshots or regenerate.

### Trust chain and CI

10. **One documented guarantee is currently false rather than merely narrow.** `.gitignore` claims the reproduce job verifies the untracked `candidates.json` / `review-queue.json` through the committed gate-2 manifest; in fact `validate_reconciliation.py:301` checks the manifest against the same run's artifacts, and the committed manifest is never compared with the regenerated one because timestamps exclude it from the diff list. Compare manifests and both `validation-report.json` with stripped timestamps (`generatedAt`, `generatedAtTime`, `dateTime`). Small to medium.
11. **The reproduction check is fail-open** toward newly emitted artifacts: the diff list is an include list and `git diff --exit-code` never sees untracked files. Add `git status --porcelain --untracked-files=all` with abort on any output. Small.
12. **The provenance chain has no hashed root.** No artifact names the raw sources (`zweig_part_01.sql`, the `zt_*` blobs) with a sha256; stages 01–04 do not import hashlib; the first hashed point is the encoding intermediate. Stage 01 should write `data/provenance/source-dump.json` with a sha256 per raw file, checked by the census. Small, highest leverage for a data publication.
13. **The citable RDF carries no provenance.** Field provenance and review status exist only in `docs/data/klawiter.json`; `klawiter.jsonld` and the entry exports assert values without origin. Stage 05 should project field provenance and review state as named `klawiter:` terms referencing the run's activity IRI. Medium; the weightiest data-model point. Related: all 3,194 entries carry `schema:author` Stefan Zweig byte-identically, including 429 non-bibliography pages (categories, help, templates), contradicting the integrity rule in `about.md` that extraction only structures present values. Restrict to ns0 bibliographic entry types; document deliberate exceptions (film, correspondence).
14. **Two JS test files run in no CI.** `tests/test_frontend_logic.py` bridges five of seven `*.test.js`; `edit_session.test.js` (the whole edit-session state contract) and `search_logic.test.js` (diacritic folding, highlight escaping, facet counting) are not bridged, contradicting `frontend.md`. Replace the five hand-written bridge functions with one parametrized over `sorted(glob("tests/*.test.js"))`, which closes the class. Also: seven of fifteen frontend modules are loaded by no test, not even syntactically (`explore.js`, the three explore visualizations, `facets.js`, `home.js`, `pages.js`, ~150 KB including the freshly rebuilt explore area); add `node --check docs/js/*.js` to CI. Both small.
15. **JSON-LD context gaps drop data on expand.** In `work-editions.jsonld` the five `pageSummaries` keys are unmapped (443 page summaries vanish for every RDF consumer); in `contested-claims.json` `sourceMatchMode`, `sourceText`, `sourceTextId` are unmapped, so the evidence's source text never reaches the graph. Four properties used in data are missing from every vocabulary serialization (`klawiter:reviewDecision` with 76 occurrences, `bindingStatus`, `reviewContract`, `reviewEvidenceSha256`) although the ontology claims every term dereferences. Add the context entries and terms, plus two tests: every `klawiter:` property occurring in output data exists in the term register, and expansion is term-lossless. Small; the tests prevent recurrence.
16. **Two smaller trust-chain checks.** A confirmed location decision (Borås, Q26040) reaches no output value, 26 publishable location links against 25 set `sameAs` targets; the validator checks "no unauthorized relation" but not "every decision takes effect" — add the second direction. `data.md` lists `candidates.json` among canonical artifacts although it is gitignored and absent, while the 6,725 published files under `data/output/entries/` appear in no artifact table. Both small.

### Frontend robustness and accessibility

17. **Missing guards on contested edition claims.** `docs/js/detail.js:235`, `:238`, `:249` access `claim.interpretations`, `claim.reviewHistory`, `claim.source.selector[0]` unguarded while the sibling `_contestedAuthorityCell` guards exactly these; a claim without source or history throws on expand. Add the same `|| []` guards and a source existence check. Small. Also `curate.js:30`: `Promise.all(...).then(this._build)` has no `.catch`, so any error in `_build` leaves the workbench spinner forever; add a visible error state analogous to `App._renderExploreError`. Small.
18. **Three computed WCAG failures.** `.badge` (styles.css:664) at 4.37:1 on every result card (11px uppercase; `#5F5F5F` on that background reaches 4.5:1, or drop the background to white); two gold focus outlines below 3:1 (`.jsonld-suggestion.is-active` at 1666, `.agent-queue-row:focus` at 2511; use burgundy or `--sz-gold-dark`); `.wikidata-link:hover` (711) drops from 5.33:1 to 2.41:1 on hover (use `--sz-gold-dark`). Plus the reconciliation buttons' focus ring at 20% alpha of a non-token burgundy (2171–2174) is invisible; use the shared 2px burgundy rule. All small.
19. **Heading, handler and bidi gaps.** `#view-results` has no h1, so the most-used view is announced nameless and the expanded-card h3s hang under no level; mark `#results-count` as h1 or prepend a visually hidden one. The explore chip bar builds inline `onclick` handlers with JS string interpolation (`explore.js:480–514`, `:731`), the pattern already documented and replaced as a defect source in `facets.js` and `home.js`; switch to the existing delegation path. `titleAttrs` (lang + dir="auto") is unused in the explore selection list, TOC/cross-references and the playground suggestions, so transliterated Arabic and Hebrew titles read with wrong phonetics there. Small to medium.

## After acceptance (1.1 stock)

**Load-path split: not worth it before 1.0.** Measured: `docs/data/klawiter.json` is 9.72 MB raw, 2.03 MB gzip; `fullBibliographicEntry` alone is 5.31 MB and dominates both the transfer and the 5.43 MB the search index chews. A split saves ~1.7 MB gzip but only moves the index cost if `ensureIndex` lazy-loads the text part itself. If later commissioned: core file plus text file, pattern already in the repo (`App._ensureReconciliation`), five consumers to route (index, Detail, Edit.evidence, the citation column of the completeness matrix, Export.fullDataset), one new pipeline artifact.

**Pipeline consolidation, in descending impact:** builder and validator run the same ten-argument build sequence as separate copies whose equality carries the determinism check (shared `load_and_build` in `lib/reconciliation.py`; medium to large); the EARL/report/manifest tail of both gate validators is a copy (`lib/earl.py`; medium); `_sha256` exists four times, `_read_json` twice, inline `json.loads(read_text)` a dozen times (move next to `load_csv`/`write_json`; small); the Wikidata constants/guard/batch-loop blocks are duplicated across both refreezing tools (medium); `pipeline/measurements/` is dead, referenced nowhere, with a stale path and false byte-reproducibility claims — delete; `data/output/entries/` writes 6,725 files no frontend, test or CI step reads, and the per-entry export lacks the contested claim contrary to `production-readiness.md` — publish dereferenceably or drop; `csv.field_size_limit` is set three times with different values process-globally; `klawiter:pageCountCandidate` is structurally always null; `validate_reconciliation.py:262` guards with the magic number 100 instead of checking every expected claim `@id` appears as a subject; `segment_editions.py:279-281` builds the manifest path by hand where `reconcile_entities.py:54-59` shows the correct PROJECT_ROOT form; `verify.py`, `inject_provenance.py` and `build_vocab_pages.py` call `main()` without evaluating the result (decide report vs gate, state it in the docstring); `03c_normalize.py:80-83` drops `ensure_ascii=False`; `build_vocab_pages.py:380-386` rmtree-deletes any directory under `docs/vocab/` when some index.html exists (require a sentinel), and its four unordered `next()` calls over the RDF graph should be `min(..., default=...)` since `docs/vocab/` is byte-checked.

**Data-model honesty:** `schema:hasPart` (936) and `schema:workTranslation` (177) carry raw citation lines as objects, violating the Schema.org range — coin raw `klawiter:` terms as done for `seeAlsoText`, keep `schema:hasPart` only where an IRI resolves (medium). Minted agent IRIs assert unresolved identity (`publisher/Ltd`, `publisher/GmbH`, truncated person names); declare them string surrogates or demote to literals except where a decision exists, and pre-mark the obvious extraction artifacts in the agent review stock (medium). `agent_verified` projected from 31 type-level decisions onto 2,434 entries reads as per-entry verification; own status value or binding to sourceOccurrences (small/medium). No decision carries `decidedAt` although the term is declared, so the promised supersession chain is unorderable; `build_review` discards `decisionId`, leaving a string join as the only back-reference (small). 443 `klawiter:sourceText/*` selector targets and nearly all `klawiter:test/*` EARL IRIs are undeclared nodes (small to medium). Three vocabulary terms (`contentItems`, `languageCode`, `locationSameAs`) describe frontend field names and occur in no canonical RDF; bind the projection via a context or mark them as projection field names (small). `docs/data/klawiter.json` does not declare itself a projection (no license, no derivedFrom, no generatedAt, prefix-form `@id`/`@type` without context; `redirectCount` 3,389 is the alias-map size, the census redirect count is 1,546) — add `_meta` (small). `WorkIdentityCandidate` has one instance and the agent reconciliation layer currently publishes zero links; declare the layer as held capacity in `data.md` rather than implying a corpus-wide state (small). `inject_provenance.py` tracks only four fields while `about.md` claims every processed field value carries a provenance class; widen coverage or narrow the claim.

**Reproducibility, broader proof:** a second full run in the same job with a varied `PYTHONHASHSEED` and a diff run-vs-run (cheap; the code reads hash-seed-safe on static review, but that is a reading, not a test); then a `windows-latest` matrix leg (the `.gitattributes` and case-collision work target exactly that and it is untested). Remove the duplicated `summary`/`field_coverage` blocks from `.github/baseline-metrics.json`, keeping only `thresholds` and `known_issues`, so the drift surface between baseline and quality report disappears instead of being monitored. Optionally give `verify.py` directional thresholds so the ratchet distinguishes improvement from regression.

**CSS:** replace the fifteen-selector `:focus-visible` list (nine interactive classes already missing from it) with a `:where(a, button, input, select, summary, [tabindex]):focus-visible` default rule plus named exceptions; introduce `--sz-burgundy-rgb` / `--sz-gold-rgb` / `--sz-cream-rgb` to collapse four parallel burgundy and two gold rgba spellings (six uses of a wrong gold triple, `rgba(184,150,62,…)`); `.geo-toggle` is `.mode-tab` re-implemented across four files; fold the 400-line appended tail after the print block into the sections and merge the four scattered media queries; the `.meta-row` zebra rule at 682 is a no-op (stripe colour equals table background); the smooth-scroll call in `app.js:819` escapes the reduced-motion block (guard with `matchMedia`); `.btn-primary`/`.btn-secondary` are the only two dead class names, and the comment describing them as historical markup hooks is wrong. Declared simplifications, measured: "colour only for meaning" fully held; "two button styles" and "one heading style" each hold with about half a dozen residual variants.

**Documentation drift** (one sweep of text corrections): README review-case figure stale (796 vs 897 in the manifest — replace with the manifest reference); floating figures in README, `data.md`, `production-readiness.md` and CLAUDE.md against the repo's own rule that running figures live in reports; `production-readiness.md` still lists the Arabic diacritic residue as open although `lib/encoding.py:140` fixed it and the output is verified clean, and names the route `#quality` where the code has `data/quality`; `data.md:109` claims approved patches exist under `data/corrections/` (the mechanism is real and tested, the stock is empty — state the contract); `pipeline/README.md` and `data/corrections/README.md` are still German against the 08-27 language decision, and `pipeline/README.md` omits `build_vocab_pages.py` and the census stage; `pytest.ini` and `test_semantic.py` reference a "category F" that `testing.md` no longer has; `.gitignore` says 6,296 entry files, there are 6,725; the frontmatter `version: 1.0` in `index.md` and `about.md` means the document version but reads as a project claim against the 0.9 state; `.github/ISSUE_TEMPLATE/` holds three unrelated templates and none for a bibliographic content error.

## Suggested order

One package before acceptance out of the sections above: defects (1–5), metadata (6–9, minutes each plus the publisher decision), trust chain (10–16), frontend (17–19). Substantial work sits only in the RDF provenance (13) and the manifest comparison (10); everything else is small. Everything under "After acceptance" is 1.1 stock in the sense of the project's existing registered-not-commissioned model.

## Verification state of this review

Test suite executed locally and network-free during the review: 497 passed, 10 skipped (two deliberate fixture skips), the 17 semantic failures exactly matching `known_issues.semantic_field_mismatches`; `node --test` green for the two unbridged JS files; `node --check` clean over all fifteen modules; `git status` clean before and after. Findings 1–5, 10, 15, and the contrast figures were verified against source, raw bytes and artifacts; the hash-seed safety claim and the manifest-comparison gap rest on static reading. Several plausible review claims were checked and discarded (adding the gitignored candidate files to the diff list is wrong by documented design). Nothing was changed by the review itself.
