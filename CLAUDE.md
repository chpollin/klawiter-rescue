# Klawiter Bibliography — Project Instructions

## Data Flow

Raw files (`data/raw/`) → 8-step pipeline → `data/output/klawiter.jsonld` + `docs/data/klawiter.json`

```
01_extract → 02_fix_encoding → 03_parse → 03b_llm_enrich → 03c_normalize → 04_classify → 05_to_jsonld → 06_validate
(SQL+BLOBs)  (Mojibake fix)    (Regex)    (Gemini Flash)   (Mappings)      (Categories)   (JSON-LD)      (Quality report)
```

Step 03b uses Gemini 3.1 Flash Lite for metadata gap-filling. It requires `GEMINI_API_KEY` in `.env` and is optional (step 04 falls back to step 03 output). Step 03c applies auditable normalization rules via external mapping tables (`pipeline/data/`): location variant mapping, publisher garbage rejection, translator cleanup, pageCount validation. The frontend JSON at `docs/data/klawiter.json` is generated by step 05 and consumed by the static site.

Optional post-processing: `pipeline/inject_provenance.py` diffs the regex output (`03_parsed.csv`) against the LLM cache to generate per-field `_provenance` metadata (regex/llm/missing) and injects it into `docs/data/klawiter.json`. `pipeline/build_triage.py` condenses `verification-report.json` + `census-report.json` into `docs/data/triage.json` (per-entry attention hints for the EIL editor). `pipeline/apply_patches.py` applies approved editor corrections from `data/corrections/` as the final overlay (provenance `editor`).

## Path Conventions

All pipeline scripts resolve paths relative to `pipeline/lib/config.py`:
- `PROJECT_ROOT` = repository root (parent of `pipeline/`)
- `RAW_DIR` = `data/raw/` (source BLOBs + SQL dump)
- `INTERMEDIATE_DIR` = `data/intermediate/` (gitignored CSVs)
- `OUTPUT_DIR` = `data/output/`
- `OUTPUT_FRONTEND_JSON` = `docs/data/klawiter.json`

## Data Integrity Principle

**The pipeline must never invent bibliographic data.** Every extracted bibliographic value (title, year, publisher, translator, location) must exist in the raw wiki source text. Coverage gaps where the source doesn't contain a value are correct, not bugs. Specifically:
- Fields left empty because the source text doesn't contain them are **correct** (e.g., anthology poems without a standalone publisher, German originals without a translator)
- Coverage gaps are only bugs if the value **is present in the raw text** but the pipeline fails to extract it (regex miss or LLM miss)
- **Linked Data enrichment is allowed**: Matching extracted entities (locations, persons) against authority files (Wikidata, GND) to add persistent IDs and derived metadata (coordinates, country codes) is a core project goal — not data invention. The entity comes from the source; the link adds LOD interoperability
- The LLM enrichment step (03b) is constrained to extract **only explicitly stated** values. It has 5 anti-hallucination layers: prompt constraint, gap-fill-only merge, structured output schema, post-extraction validation, and mojibake re-validation. Verified: 0 hallucinated values found in full audit
- Provenance tracking (`_provenance` metadata) marks each field as `regex`, `llm`, or `missing`, and as `editor` once a person has verified it (set by `apply_patches.py` from the correction store)

## Key Technical Decisions

- **No MySQL**: Pipeline parses SQL dumps and BLOBs directly (Latin-1 encoding for BLOB processing)
- **Vocabulary blend**: Schema.org + Dublin Core + `klawiter:` namespace (implemented in `pipeline/lib/vocabulary.py`, documented at `docs/vocab/index.html`)
- **16 entry types**: 15 content types + redirect, mapped to Schema.org types (Book, Article, Play, Movie, etc.)
- **Static frontend**: Vanilla JS modules in `docs/js/` + custom CSS (SZD design) + FlexSearch + D3.js v7, no build step. Content pages: About, Methodology, Help, Data, JSON-LD Playground, Imprint. EIL editor (`edit.js` + `detail.js`) is localhost-only
- **Exploration interface**: 3-mode interactive visualization (Timeline with Bars/Sparklines/Ranks, Geography globe/flat toggle, Connections network) with URL state persistence and cross-view filtering
- **Wikidata reconciliation**: geocoded locations reconciled against Wikidata via Reconciliation API, most carrying Q-IDs. Script: `pipeline/reconcile_locations.py`. Current counts and Q-IDs live in `docs/data/locations.json`
- **Test suite**: pytest suite in `tests/` (run `pytest --collect-only -q` for the current count). Categories: Census (completeness — all page_ids, no dupes), Schema (every entry — types, ranges, markup, mojibake), Consistency (cross-field — German+translator, film+pageCount, seeAlso integrity), Distribution (regression ≤1pp against baseline), Extraction (unit + real-data + LLM-judge), Semantic (wiki-verified ground truth + heuristic validators), Normalization (`test_normalize_unit.py` rules + `test_normalization.py` output), Provenance (`test_inject_provenance.py`), Triage contract (`test_triage.py`), Patch contract (`test_apply_patches.py`, `test_patch_contract.py`), Frontend logic (`test_frontend_logic.py` bridges `evidence_triage.test.js` via node). Shared fixtures in `conftest.py`. See `knowledge/testing.md`
- **Semantic testing**: entries verified against the archived wiki (klawiter.stefanzweig.digital), heuristic validators on all entries. Ground truth in `tests/wiki_ground_truth.json`. Run with `pytest -m semantic`
- **Pipeline limit**: Regex extraction reached diminishing returns. Multi-edition pages (a few hundred, see `knowledge/production-readiness.md`) cause systematic extraction errors because one flat record per page mixes the work level with the edition level. Further regex fixes shift problems rather than solving them. See `knowledge/pipeline.md`
- **Regression testing**: Baseline metrics in `.github/baseline-metrics.json`, 19 regression tests in `tests/test_regression.py`, CI checks in `validate-patch.yml`
- **GitHub Pages**: Deploy from `docs/` folder — live at `https://chpollin.github.io/klawiter-rescue/`
- **License**: MIT (code) + CC BY 4.0 (data)

## Source Data Coverage

- Database has 6,725 pages total; pipeline extracts **all namespaces** (6,296 bibliography entries in ns 0, plus 420 category pages and 9 system pages)
- Frontend displays ns 0 entries only; category/system pages are included in JSON-LD but filtered in the UI
- Only `zweig_part_01.sql` is used; `_02` (empty schema) and `_03` (system metadata) are correctly ignored
- BLOBs contain 53,016 text entries (all revisions); pipeline uses only the latest revision per page
- 1 stub entry: page_id 2979 ("A unidade espiritual do mundo") — text_id 18046 not in any BLOB; present in output as a stub with the page_title as title and no bibliographic content

## Known Limitations

Current coverage figures live in `data/output/quality-report.json` and in the `_meta` block of `docs/data/klawiter.json`; the frozen regression reference is `.github/baseline-metrics.json`. Do not restate those numbers here — they change with every pipeline run.

- Publisher: roughly half the entries carry a publisher. The rest is not in the source text or in implicit citation formats — these gaps are correct per Data Integrity Principle
- Translator: many entries are German originals or don't name a translator — these gaps are correct
- Titles are clean of markup residue and section headers ("Contents:", "See:", etc. rejected with page_title fallback). A known set of titles has encoding artifacts in page_title (Arabic/Cyrillic transliterations); frozen count in baseline `known_issues`
- Multi-edition pages contain multiple publications while the pipeline extracts one flat entry per page. Publisher, pageCount, year may come from the wrong edition. See `knowledge/production-readiness.md` for the target work/edition model
- Page count coverage is limited: `pp. N-M` page ranges are ranges within a container, not book lengths, and are deliberately not extracted
- A small residue of bracket-titles remains where no page_title fallback exists. Title extraction searches for the second bold block on `[year]:` patterns before falling back to page_title
- Title precision: verify.py underreports because page_title fallbacks count as false positives; they are classified `correct_fallback`
- JSON-LD namespace URL (`chpollin.github.io/klawiter-rescue/vocab/`) resolves to `docs/vocab/index.html` (GitHub Pages)
